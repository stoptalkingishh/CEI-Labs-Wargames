# Per-Track Game Guide Brief

Create one participant deck for each released track. These decks introduce the
track's purpose and mechanics without giving a working solution, payload, path,
or command for a specific challenge.

## Required structure

1. Cover: track name, learning focus, and current catalog scope.
2. Map: concept groupings drawn from the current learning objectives.
3. Theory: one generic textbook concept per slide.
4. Getting in: the current Start Here and launch flow.
5. First flag: explain the safe onboarding journey without revealing a level
   solution.
6. Ready to play: where to get hints, help, and the next instruction.

## Content rules

- Treat `docs/<track>/learning-objectives.md`, the generated Start Here
  challenge, and `docs/participant-quickstart.md` as authoritative.
- Use generic examples only. A deck must not contain an actual-level payload,
  route, credential, flag, or solution command.
- Generate both plain and illustrated variants from one source if variants are
  offered; never hand-edit only one binary deck.
- Recheck copy for overflow and accessibility before publishing a deck.

## Staff additions

For a staff-only deck, add the role split, preflight, start/lock/hide/close
sequence, incident response, and evidence checklist from
`../docs/staged-game-operations.md`.
