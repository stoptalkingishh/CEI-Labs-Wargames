# Learning Objectives

A skills inventory for the three primary self-hosted wargame tracks (76
levels total), organized by concept rather than by level number — to check
what a participant has actually learned, to plan which levels to assign
for a given skill gap, or to compare against a course syllabus. Each
track's full inventory now lives in its own folder alongside that
track's writeups and cheat sheet:

- [`Bandit`](../tracks/bandit/learning-objectives.md) —
  Linux fundamentals (34 levels)
- [`Krypton`](../tracks/krypton/learning-objectives.md) —
  classical cryptography (7 levels)
- [`Natas`](../tracks/natas/learning-objectives.md) — web application security
  (35 level endpoints, 0–34; levels 15–34 are currently inert/pending release)

Additional tracks have their own objectives and release boundaries:

- [`Sentinel`](../tracks/sentinel/learning-objectives.md) — defensive security
  analysis (5 implemented pilot labs plus 6 deferred expansion labs)
- [`OSINT pilot`](../tracks/osint/learning-objectives.md) — three reviewed
  artifact-investigation methods, exported from an external plugin
- [`Threadline`](../tracks/threadline/learning-objectives.md) — 42-lead OSINT
  campaign, hidden by default and non-staged

## Cross-track meta-skills

These aren't tied to any single level, but are reinforced throughout
the primary self-hosted tracks:
- Reading unfamiliar tool documentation (`man <command>`) under time
  pressure and extracting the one relevant option.
- Distinguishing "I don't know this concept" from "I know the concept
  but forgot the syntax" — and using the right kind of help for each
  (a bare reference vs. a fuller explanation).
- Methodical enumeration: checking a small, well-defined search space
  exhaustively (a byte range, a port range, a PIN space) rather than
  guessing.
- Reading source code (shell scripts, PHP, cron configs) to understand
  *why* something behaves the way it does before acting.
